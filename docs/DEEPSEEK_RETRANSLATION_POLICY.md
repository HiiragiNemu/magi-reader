# DeepSeek 剧情重译政策

本文件记录社区剧情重译流水线必须执行的硬边界。它不是剧情译文，也不改变任何既有人工或官方文本。

## 保护边界

- 已由 provenance、可信 `main` 基线、人工清单或交叉证据确认的官方/人工中文只读保护。
- 台服官方文本及其经过可审计繁转简流程生成的文本只读保护；`7_Namae` 采用同一最高优先级。
- 来源不明、人工/官方标识冲突或证据不足的条目进入待核实清单，不进入翻译 worker。
- 只有明确列入 Codex allowlist 的旧机翻，或缺少受保护中文的日文原文，才能进入重译批次。

## Worker 边界

- Codex 负责来源判定、证据检索、术语库、上下文包、批次选择、文件写入、测试和最终复核。
- DeepSeek worker 只读取 Codex 提供的封装翻译包并返回结构化译文、术语命中和未决项。
- Worker 不访问仓库，不使用任何工具或 MCP，不判定 provenance，不修改文件，不运行测试，不发布。
- 上下文或批准术语不足时必须返回 `unresolved`，不得凭模型常识猜译。

## 称呼规则

- DeepSeek 新生成译文中，人名或昵称后的 `ちゃん` 使用“小 + 已批准称呼”。
- 明确示例：`ういちゃん` / `忧ちゃん` 采用“小忧”。
- 同类示例：`いろはちゃん` 采用“小彩羽”，`灯花ちゃん` 采用“小灯花”，`ねむちゃん` 采用“小音梦”。
- 禁止在新译文中保留 `ちゃん`、`chan`、`-chan`、`－chan`、`—chan` 或“酱”。
- `赤ちゃん`、`おばあちゃん`、`ちゃんと` 等词汇结构按完整词义翻译，不做字符级全局替换。
- `さん`、`さま`、`くん`、`先輩` 等其他称呼根据已批准人物关系和语境处理；没有证据时进入 `unresolved`。

## 发布硬门

正式写入前必须同时满足：

1. 受保护文件的基线 SHA-256 与发布前 SHA-256 完全相同。
2. `7_Namae` 台服权威映射和保护计数闭合。
3. DeepSeek 输入条目与 Codex allowlist 完全一致。
4. DeepSeek 输出只包含协议允许的翻译结果字段。
5. 事件、行数、说话人、标签、变量、占位符、控制码和换行语义保持等价。
6. `ちゃん`、罗马字敬称、连字符敬称和“酱”扫描为零违规。
7. 可播放 JSON 与规范 TXT 的双向重建、复开和回滚演练通过。
